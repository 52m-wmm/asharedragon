# AShareDragon v0.5.1：龙头标签稀少原因诊断

审计日期：2026-11-07。标签版本 `dragon-cycle-v1.1`，规则版本 `historical-l1-v1.1`。本次使用本地真实行情、既有事件缓存和公开公司公告；没有调用付费代理，没有补造涨停事件，没有降低发布标准。

## 结论与六个问题

1. **为什么 1,248 个候选只有 371 个边界完整周期？** 734 个起点无法确认，另有 143 个起点已知但终点未知，合计 877 个不完整。按首个阻断原因互斥归因，693 个被历史 ST 状态缺失阻断，117 个到达审计区间末端。缺失证据不能当作未涨停。
2. **为什么只有 1 个达到 5 板？** 这是“边界完整周期的最高高度”筛选结果，不是历史全市场龙头总数。已知起点且已达到 5 板的有 2 个；其中豫能控股结束边界未知，最高高度保留 NULL。只有青岛食品的 6 板周期边界完整。
3. **哪个环节损失最多？** 首先是上游范围限制：生产审计只有 2020-12-01—12-31 和 2026-10-26—11-04，共 31 个交易日，占行情实际覆盖 2,389 个交易日的 1.30%。范围内，历史 ST 状态缺失是周期边界最主要的阻断原因。
4. **已知历史案例为什么没识别？** 指定的五个案例年份均不在生产审计区间内，对应年份本地涨停 U 事件缓存为 0。它们不是经过完整历史筛选后被否定。日线能提示连续上涨停价的片段，但独立限价、历史状态与完整事件证据尚不足以发布标签。
5. **修复需要哪些数据？** 需要连续区间的可追溯涨停事件、历史 ST/交易状态、特殊交易日与除权参考价、独立历史限价验证，以及区间两端足够的前后交易日证据。只增加价格行或默认所有股票非 ST 无法解决。
6. **能否先发布部分可信年份？** 当前不能发布任何完整年份的正式标签。2020 年 12 月只有诊断条件较完整的月份样本，2026 年只有短窗口；严格门槛仍未通过。以后可按明确股票和区间逐批验收，不能把局部验收外推到全年。

## 数据范围和漏斗

行情仍为 10,343,963 条、5,474 只股票，2017-01-03—2026-11-06。唯一股票交易日数和通过基础 OHLC 有限值、正值及高低价关系检查的行数均为 10,343,963。这不等于历史应有股票交易日全覆盖。

已记录的全历史缺失股票交易日为 125,036，其中原有 2026 年补采区间缺口 1,790 保持质量标记。缺口可能包含停牌等多种原因，不统一解释为停牌或零收益。全库仅 51,317 行具有历史 ST/交易状态字段，占 0.4961%。独立历史限价验证记录为 0。

来源自行报告“连板数为 1”的行有 1,206；价格诊断支持其中 1,180 行。但来源字段不能替代前一交易日的独立边界判断，因此不能直接得到 1,180 个可信首板。事件交易日聚合为周期也不是样本“误删”。

## 边界损失的逐项归因

按当前事件无法确认优先、否则左边界优先、最后右边界的规则，对 877 个不完整候选分配一个首要原因。这个表是互斥计数，不代表每个周期只有一个问题，也不表示补齐一种字段就能直接恢复相同数量的正式样本。

| 首个阻断原因 | 周期数 |
|---|---:|
| 历史 ST 状态缺失 | 693 |
| 到达审计区间末端 | 117 |
| 旧制 IPO/重新上市状态 | 35 |
| 前序已涨停但起点被截断 | 15 |
| 日线缺失 | 8 |
| 特殊交易日缺少官方参考价 | 4 |
| 来源或规则冲突 | 3 |
| 重复/冲突事件 | 2 |
| 合计 | 877 |

693/877 = 79.02%。全审计股票日期网格中，诊断 unknown 的原因计数为：历史 ST 缺失 67,329、日线缺失 535、规则范围外 46、退市窗口需官方限价 36、上市交易日序号缺失 23、旧制上市/重新上市 22、来源或规则冲突 18、特殊交易日 7。它们的单位是股票交易日，不能与上表周期数相加。

诊断规则可借助当日来源事件建立候选，但相邻“没有来源涨停记录”的日子仍需证明为未涨停。不能把事件池不存在某股等同于该股未涨停，也不能在历史 ST 未知时统一套用 10% 限价。

## 算法审计和已修复问题

| 检查项 | 结果 |
|---|---|
| 跨月、跨年 | 状态机按完整交易所日历连接，不按月重置；增加跨月及跨年回归测试 |
| 周末、国庆、春节 | 不按自然日差值断连；圣龙国庆及克来春节片段可连接，补充节假日回归测试 |
| 缺日线与未涨停 | 缺失保持 unknown，不可作为阴性边界；缺事件也不能凭价格计入正式连板 |
| 停牌 | 既有定义是交易所连续交易日连板，确认停牌终止当前周期；不是跨停牌累计的另一种口径 |
| 复牌/重新上市 | 未验证特殊交易日保持 unknown；不默认恢复普通限价 |
| 除权除息 | 使用未复权价格及参考价证据；未经批准的复权因子继续隔离；价格窗口参考价断裂不得直接解释为收益 |
| 板块制度与 ST | 按已有日期有效规则判断，保留创业板制度变化、科创板、IPO、ST 特殊规则测试；无历史状态不放宽 |
| 周期起止 | 前一日涨停或未知不能种出可信首板；末端未知仅删失最终高度，已观察到的里程碑仍保留 |

确认并修复三项实现问题，均先以失败测试复现：

1. **无价格行时忽略已验证停牌证据。** 原实现提前返回 `daily_missing`；现在显式停牌且无冲突时返回 `suspended`，没有停牌证据仍返回 unknown，停牌与涨停事件冲突仍为 unknown。中通的 15 天在案例审计中获得解释，不生成价格或正标签。
2. **来源筛选后沿用全来源覆盖率。** 原 AKShare 筛选可把 2020 年 12 月当成有覆盖的零样本月；现在按来源保存/使用覆盖证据，AKShare 该月 `eligible=false`、`first_boards=NULL`，Tushare 缓存该月诊断完整周期为 43。没有来源覆盖证明时也返回未知，不返回伪零值。
3. **正式查询过度信任单行 `formal_eligible`。** 现在必须同时通过快照发布验收、单行来源/规则/覆盖/严格事实验收、完整周期和已知起点/最高高度，才可标为 verified。修复防止不一致快照泄漏到正式统计；当前原本就是 0 条，未发现已发布错误正式标签。

修复前后核心候选数均为 1,248/371/1。未发现月份重置、周末计算或节假日连接错误导致本次稀少结果。现有窗口截断是范围和证据问题；不能用降低规则要求掩盖。

## 三级状态与正式发布

- `verified`：来源、规则、覆盖和严格事实均验收，通过快照发布门槛，且周期起止完整。当前 **0**。
- `diagnostic`：已有可定位首板的候选，但证据未全部验收。当前 **514**，其中 143 个最终高度未知。
- `unknown`：候选连首板起点也无法可靠定位。当前 **734**，保留观察片段供审计。

这是周期记录状态；字段另有独立质量状态。最终高度 unknown 仍为 **877**，不能因为 143 条记录整体为 diagnostic 就把未知终点当成已知。正式模式只接受 verified；诊断模式可显式包含 unknown。新增只读接口 `GET /api/research/dragons/diagnostics` 返回漏斗、排除原因及五个案例，并声明价格情景不属于标签。

后续优先选择一个有连续可追溯事件和状态证据的区间，补齐前后边界，再扩大范围。独立限价或经认证的除权参考价、历史 ST 与停复牌/上市/退市状态缺一时继续保留 unknown。不能仅因某月缓存完整就批准全年，也不能把默认非 ST 的情景输出转成正式样本。
