# AShareDragon v0.5.3：历史 ST 证据与下一质量瓶颈

执行日期：2026-11-07（America/Los_Angeles；机器审计时间为 2026-11-08 UTC）。本轮没有下载全市场 OHLC，没有请求付费代理，没有重构 UI、训练模型或 Push。

## 结论

1. **namechange 能否可靠恢复历史 ST？** 可以辅助恢复有明确有效区间的历史简称及风险警示标记，但不能仅凭名称历史的一部分证明全时期非 ST。需要证明返回完整、起止有效日期正确、区间不重叠，并补核特殊简称、遗漏变更及交易所实施公告。当前本地没有可关联的 `namechange` 或 `st` 原始记录，无法以它们新增真实状态。
2. **哪些年份有完整历史状态？** 没有。2017—2020 年缺少可关联的独立 ST 观察；2021—2026 只有稀疏日期/股票样本，不能发布完整年度状态或季节性结论。
3. **五个案例能否正确识别？** 关键启动区间仍缺 ST、交易状态、独立限价及特殊交易日证据，首板/最高高度继续为 unknown。72 个具体股票日期的字段缺口已逐项导出。
4. **verified 是否增加？** 没有，仍为 0；新增严格可验证周期 0、正式 L1 标签 0。原 693 个首要 ST 阻断解决 **0/693**。现有 diagnostic=8,455、unknown 候选=11,179 保持不变。
5. **下一项最大阻断是什么？** 对这 693 个周期，只假设补齐 ST 后，693 个仍首先被 `historical_trading_status_missing` 阻断。再后面仍需要特殊交易日证据、独立限价或经认证的除权参考价，以及连续事件和周期边界。不能把 ST 补齐当成发布门槛已全部满足。

## 二、namechange / st / stock_st 的使用边界

| 接口 | 可提供证据 | 必须检查 |
|---|---|---|
| namechange | 历史名称、有效开始/结束日、公告日、变更原因 | 请求的 start_date/end_date 是公告日期过滤，不能当作有效日期过滤；先按代码获取完整历史，再裁切有效期 |
| st | 风险警示操作及原因、发布日和实施日 | 生效时间采用 imp_date；必须有实施/撤销状态的连续证据，不能仅从第一条观察向前推断 |
| stock_st | 指定交易日的风险警示股票列表 | 正向成员证据有效；只有全量列表完整性及市场范围被证明后，才可考虑非成员的阴性证据 |

上述字段语义依据 [namechange 官方文档](https://tushare.pro/document/2?doc_id=100)、[st 官方文档](https://tushare.pro/document/2?doc_id=423)、[stock_st 官方文档](https://tushare.pro/document/2?doc_id=397)。`st` 和 `stock_st` 文档均列单次最多 1,000 条；本次访问的 `namechange` 页面未明确列出上限/分页契约，不能擅自把 1,000 当成已验证保证。此处只是官方文档能力，不是本地已经获得权限或数据。

实现保留有效期与公告日两个字段，开放终点必须有明确 as-of 截止日期。重叠区间标为 conflict，缺失区间保持 unknown。分页检查拒绝重复页、偏移跳号、未证明上限的单页结果，以及没有总量证明的满额终页；未经完整性证明的普通名称不得产出非 ST。

`ST`、`*ST`、`SST/S*ST` 分别保留；`PT`、`S`、除权/除息标识和其他特殊简称不自动解释为普通非 ST。风险警示标识的历史含义需与适用制度结合，不能直接映射成某个固定涨跌幅。参见 [深交所关于 ST/*ST 标识的说明](https://investor.szse.cn/knowledge/company/st/t20171113_538693.html)。上市公司公告可作为某个明确股票日期/区间的独立证据，但不能把一个案例公告扩展为全市场完整历史。

## 三、统一 historical_stock_status 与证券身份

新增独立 Parquet 时间轴 `historical_stock_status.parquet`，当前 **75,461 行**：56,531 条状态来源观察，加 18,930 条带交易日期的历史事件名称属性。后者并非完整名称变更历史，普通名称不自动产生非 ST。

字段包括：`security_id,stock_code,exchange,valid_from,valid_to,historical_name,risk_warning_status,trading_status,evidence_source,evidence_quality,fetched_at,verification_status,evidence_id`。区间终点为包含关系；当前来源大部分是单日观察，因此采用同一天的 valid_from/valid_to，**不前向填充到下一次观察**。来源重复和冲突保留，查询时冲突返回 unknown，不按最新来源覆盖。

上市期外另标 not_listed 或 delisted，不能视为停牌；身份区间存在歧义时继续 unknown。风险警示和交易状态独立：例如 ST 股票可能正常交易；停牌并不能证明非 ST。采集时间不明单独标注 `observed_time_unknown`，并不伪造 PIT 可用时间。

所有关联键均采用 **标准化代码 + 交易所 + 有效日期**。公共标准化函数现在统一接受 `002432`、`SZ002432`、`sz.002432`、`002432.SZ`，输出 `002432.SZ`；矛盾交易所、缺位代码和股票名称作为代码均拒绝。

另建 `security_aliases.parquet`，当前 5,565 个代码/上市期映射。内部 ID 是由代码、交易所和上市起日确定的稳定上市证券 ID，不包含股票名称；更名不改变 ID。代码复用的不同上市期产生不同 ID；无法唯一解析的重叠区间返回 identity_ambiguous。跨代码延续同一证券只能使用有来源证明的别名映射，不能根据同名或相似名称自动建立。本地尚没有经过核验的跨代码变更链，因此没有捏造跨代码身份关系。既有 PostgreSQL 股票观察记录和业务模型不迁移、不重建。

### 现有关联代码审计

检查了 ingest、analytics、research、API 和脚本中的 JOIN、merge、去重、分组与键访问。未发现以股票名称为行情 JOIN、去重或标签主键的路径。`stock_name` 的现有用途是展示、搜索、或按已确定代码/日期读取名称；题材名称查询不属于证券身份关联。

确认并修复的是公共标准化函数拒绝 BaoStock `sz.002432` 的入口不一致；既有 BaoStock 专用适配器以前自行转换，所以不能把它误称为已造成全库代码丢失。回归测试同时覆盖代码复用、显式跨代码别名、更名属性不改变身份和歧义拒绝。原始 Parquet 代码未被批量改写。
